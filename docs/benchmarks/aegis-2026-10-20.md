# Aegis optimization measurements — 2026-10-20

These are local development measurements, not portable performance targets.
Renderer: Codex in-app browser, 1629 × 1602 backing resolution, pixel ratio 1.5,
production artwork at 100% render scale. Initial Aegis camera, stationary player,
16 initial mixed-fleet fighters. The render comparison uses the same frozen
scene, 20 warm-up + 90 measured frames per block, OFF/ON/ON/OFF order.

| Frozen scene | Before: ship off / on | After: ship off / on |
| --- | --- | --- |
| CPU render submission | 0.67 / 0.91 ms | 0.68 / 0.96 ms |
| Submitted draws | 31 / 134 | 6 / 109 |
| Submitted triangles | 379,117 / 425,009 | 133,892 / 179,784 |
| Browser frame interval | 13.32 / 13.32 ms | 13.32 / 13.32 ms |

The complete ship is visible at this viewpoint: its own 103 draws / 45,892
triangles remain necessary. The large reduction here comes from skipping
other off-screen static actors. A live turn away from the ship reduced total
scene submissions to six draws while PD continued firing and hitting; geometry
returned on turning back. The frame interval is refresh limited; CPU timing
excludes GPU execution. There is no demonstrated render-CPU speedup. Culling
removes invisible GPU work, with a small CPU cost for bounds tests.

CPU replay compares current code with targeting/resolver source from commit
`62fb328a78cb2af94b9ec33ed9791a81d275af4a`, using identical current assets,
scripted poses, real mesh collision, damage and six seconds of 60 Hz updates.
Three samples per case follow warm-up, with reference/current ordering reversed
on alternate samples. Actual shot/hit counts and each fighter's health must
match exactly; no timing thresholds gate correctness.

- Eight fighters firing: reference 5.280 ms/update; optimized 5.279 ms/update.
  Difference is below noise; collision dominates. Both produce 872 shots / 802
  hits with exactly matching health. Raw data: `aegis-cpu-comparison.json`.
- 128 contacts, weapons disabled to isolate targeting: reference 0.609 ms/update;
  optimized 0.248 ms/update, about 59% less CPU. This is a targeting stress test,
  not an ordinary battle or a full-flight FPS measurement. Raw data:
  `aegis-targeting-comparison.json`.
- The original standalone eight-fighter run measured about 3.75 ms/update. Its
  raw data is retained in `aegis-cpu-initial.json`; different machine load means
  that standalone result should not be subtracted from later runs.

Reproduce from repository root:

```text
node tools/benchmark-aegis-encounter.cjs
node tools/benchmark-aegis-encounter.cjs --reference 62fb328a78cb2af94b9ec33ed9791a81d275af4a
node tools/benchmark-aegis-encounter.cjs --reference 62fb328a78cb2af94b9ec33ed9791a81d275af4a --contacts 128 --no-fire
```

Browser: open `experiments/flight.html?aegis=1`, press F3, choose **Benchmark
Aegis on / off**. This benchmarks the current viewpoint. Reset first to recreate
the initial camera and combat snapshot. Keep the foreground tab, size and
settings unchanged throughout a run. The benchmark restores the ship and leaves
flight paused.
