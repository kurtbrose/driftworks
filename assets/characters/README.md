# Character source assets

Quaternius Astronaut and Standard Universal Animation Libraries 1 and 2, supplied by the user on 2026-10-16. Every pack has unmodified files in `original/` and a `provenance.json` with acquisition details, creator URL, license evidence and SHA-256 for each source file. The animation-library ZIPs were removed after extraction; their original filenames and hashes remain in provenance. Character ZIPs are ignored by Git.

Open [the character and animation viewer](../../experiments/characters.html) through the local HTTP server. The catalog includes six glTF/GLB exports. Select a model and clip; pause, scrub, adjust playback speed, or show the skeleton. Source materials, textures, rigs, original dimensions, and root motion are preserved. Nothing is wired into gameplay yet.

The astronaut includes 24 embedded animations. Its [Poly Pizza listing](https://poly.pizza/m/3hC2i0CTuO) credits Quaternius and identifies the license as CC0. The original download filename and bytes are preserved in `quaternius-astronaut/original/`.

The astronaut viewer offers separate suit and trim colors, four crew palettes, and an Original option. Swaps preserve the dark hardware and material finish, and leave the source GLB unchanged. Palette controls are disabled for the animation-library mannequins.

Universal Animation Libraries 1 and 2 each contain 43 clips in both in-place and root-motion variants. The female mannequin is a separate static retargeting target. Applying library clips to the astronaut requires retargeting; use the included authoring files and creator setup guides.

`python tools/organize-character-packs.py` verifies every extracted source against its recorded hash and rebuilds the catalog without needing ZIPs. No conversion or package manager is needed at runtime. The viewer uses the pinned MIT-licensed Three.js r180 subset in `vendor/three`, with its own source hashes and license; all runtime URLs are relative and local.

## Reusing astronaut deformation

`createBodyModel(root)` in `experiments/character-bodies.js` manages one astronaut
instance. Pass a dedicated, unanimated wrapper containing its meshes and skeleton;
keep placement and animation ownership with the scene. Each worker must already
have its own skeleton. The controller clones geometry, not the rig or materials.
Its coordinates are specific to the supplied astronaut's Z-up source meshes.

```js
const body = createBodyModel(workerRoot);
body.apply(guardBody(randomBody()));
// Change shape later using the same saved source baseline.
body.apply(guardBody(nextShape));
body.reset();   // Restore positions, normals, initial scale and culling flags.
body.dispose(); // Restore source geometry and release only owned geometry clones.
```

The controller captures rest positions and normals, updates vertices and GPU
attributes, recomputes normals and geometry/mesh bounds, and scales the complete
mesh-and-rig wrapper relative to its initial scale. Shaped meshes disable frustum
culling because cached pose bounds become stale during animation. Shapes with no
local deformation restore the original normals and culling flags. Shape changes
always start from the captured baseline, so they do not accumulate distortion.
Shared source geometry and other model instances remain unchanged.

Call `dispose()` before the scene disposes its model resources. It is idempotent;
applying a shape after disposal throws. The caller still owns the animation mixer,
source geometry, materials, textures and skeleton. Crew guardrails are explicit:
`apply()` accepts the provided shape unchanged, so use `guardBody()` for crew mode
and omit it for stress tests. The viewer uses this same API and releases its
controller when switching models.

## Fighter cockpit study

`fighter-cockpit.js` is generated by `node tools/bake-fighter-cockpit.mjs` using vendored Three.js. It freezes the original astronaut in a seated pose by aiming its existing leg, arm and foot bones, then bakes the skinned triangles with source material colors. Crew height is calibrated to a 1.8 m standing astronaut; coordinates are meters relative to the hips, forward +Y and up +Z. The same bundle includes the local Kenney armrest/headrest chair (see its pack README). Source GLBs remain unchanged; the static study needs no runtime loader or external dependencies.

The seated bake keeps each shin aimed at its own end bone and explicitly moves the astronaut's independent root-parented foot controls to the new ankles. Bone lengths and ankle attachment are checked during generation. Chairs are rotated to face the same +Y direction as the crew.

## Walkable crew deck study

Open [Crew deck](../../experiments/crew-deck.html) through the local server.
WASD walks, Shift hurries, mouse capture looks around, E talks to nearby crew,
and Escape stops walking. If mouse capture fails (including in the embedded
browser), drag on the scene to look; movement remains available after Walk aboard.
Native resolution with MSAA is the default (DPR capped at 2); optional pixelated
modes remain in the Pixels menu. Low-poly geometry does not require low resolution.
The room and crates have simple horizontal collision bounds; this is a flat-floor
hub experiment, with no stairs, combat, saved campaign state or mission integration.

Three astronauts share the original GLB's geometry and 24 animation clips.
Each clone has independently rebound bones, an animation mixer and cloned materials
for palette changes. Two idle; one patrols; interaction turns the actor toward the
player and plays Wave. All loaded assets and renderer dependencies are local.
The source remains unchanged. The GLB is 1,899 KiB uncompressed, downloaded once
for the cast. This is a source-asset prototype, not a minimal shipping export;
removing unused clips and measuring compression is a useful next size experiment.
Universal Animation Library clips need retargeting to this astronaut; this scene
uses its embedded Idle, Walk and Wave instead. The Synty reference image describes
an aesthetic; no assets or licensing rights are inferred from that image.

Browser verification on 2026-10-23: independent idle/patrol animation, movement,
nearby E interaction and dialogue, plus mouse-capture failure fallback. At a
1,280 by 720 CSS viewport, 427 by 240 backing buffer, DPR 1, no shadows or
postprocessing, after loading and warm-up, a stationary near-crew view showed
88 draws / 32,262 submitted triangles with crew and 49 / 588 without. The
one-second rolling median CPU render submission was about 0.8 ms versus 0.4 ms;
frame median was 13.3 ms in both, with observed p95 around 13.4–13.6 ms.
Background repository checks were running, so these timings are provisional.
These are browser observations, not GPU timing or a general performance budget;
NPC animation continues when hidden. Source geometry and clips are already shared.
The on-screen stats and Crew toggle support further comparisons. A focused Node
regression checks shared geometry, independent skeletons, palette ownership and
source preservation (`node tests/crew-deck.cjs`).

### Authored heads and portrait-guided skins

Crew deck uses derived heads from the CC0 Quaternius Universal Base Characters
male and female Superhero models. Their authored geometry, UVs and normals replace
the earlier procedural head and portrait-projection experiments. Original source
files remain untouched. Extract with `node tools/extract-crew-head.mjs female` or
`node tools/extract-crew-head.mjs male`; the derivation keeps complete triangles
above the neck cutoff that belong to the neck/head bone chain, excluding shoulders.
The resulting rigid head follows the astronaut's animated Head bone in metres.

Jo, Luis and Asha have separate first-pass skin variants guided by their approved
runway-worker portraits. Built-in ImageGen edited the skin UV atlases; source
geometry and UVs stayed fixed. Exact prompts, references and output hashes are in
the `runtime/*-skin-v1-generation.json` files. Generated derivatives are separate
from unmodified CC0 sources. Runtime consumes packed WebP derivatives of those PNGs.

The Skin selector restores original or guided skin and eyebrow color. Shared hair
pieces remain fitted in both modes. Inspect selects an identity, while Head front,
Head ¾ and Head profile provide unobstructed comparison views with the matching
comms portrait. No facial mesh animation or synchronized lip motion is claimed.
Likeness is preliminary; source anatomy constrains facial proportions, and the
remaining three cast entries are still explicitly marked as base templates.

## Shared cast pipeline

Crew deck now reads `crew-cast/catalog.json`, built from the existing comms roster
and `crew-cast/recipes.json`. Inspect selects six identities without creating a
new suit or rig. The matching comms portrait, voice ID, role and personality come
from the same record as the 3D recipe. Two authored head templates and origin-zero
hairstyles are cached and reused. Hair placement subtracts each source Head pivot;
head extraction also requires neck/head bone influence so shoulders are excluded.

Geometry is indexed/interleaved in small binary buffers. Runtime skin/hair maps
use 1024px maximum WebP quality 90; comms WebP atlases retain all seven 256px frames.
Editable originals remain intact. The viewer caches at most eight skin resources
(active ones pinned) and four decoded comms atlases, releasing replaced face
materials while retaining shared geometry. These are experiment-local caches;
the production radio renderer has not been migrated to this catalog.

See [the cast workflow](../../docs/character-cast.md) for authoring, build commands,
measured byte costs, generation briefs, limitations and the 100-record test.
